从住宅建筑平面图的 DXF 文件读取墙体、门窗图层元素：提取墙轴线、推断门窗嵌入线，完成骨架化表示与房间识别/分割。

当前这个项目，是从dxf图纸中读取特定几个图层的元素信息，完成骨架提取的一个库。我的目标是：
任意给定一张建筑平面图，读取墙体图层，提取轴线；读取门窗图层，确定门洞（窗洞）嵌入线，也就是既有的墙体轴线上两个点的连线，它们所在的位置处安装了门窗。由于最终所有的构件都变成了单线表示，整个建筑平面图就形成了一个轴线骨架。
当前的实现比较复杂，包含这样几个主要模块：
dxf_utils：负责从dxf中读取最原始的图元信息，由于实际图层可能包含嵌套块，需要递归处理。现在有个问题是会把所有元素都变成线段。
linework_axis_extractor：墙体轴线提取模块，基本的逻辑是先对原始线段初步校准，然后针对水平、垂直线段按可能的墙厚做匹配，然后去平行线中线作为轴线，最后做延伸确保轴线相连
opening_embedment, opening_clustering：门窗等开口构件的嵌入线识别，这部分逻辑比较绕，而且效果不是很好。因为门、窗的样式不一样，而能够获取到的是每一个最原始的线元、弧线，需要先根据距离聚类找到每个门窗元素几何，再通过各自的判别准则找到嵌入线。这是我不太满意的一个模块，需要重点考虑新的实现方法。（我先把opening_embedment删除了，它实在太长了，直接重新实现，避免受现有实现影响）
cad_processor: 将各个步骤整合的一个模块，从dxf读取信息，墙轴线提取、门窗洞口嵌入线提取，以及校准，确保空间能够闭合，之后再通过房间识别和矩形分割，将整个平面图划分为多个矩形。

最核心的是骨架提取的两个模块，需要保证它们提取的准确，同时又要让代码清晰、简洁。之前为了开发出功能，代码都塞在一个文件中，一个模块可能长达七八百行，非常臃肿，我只知道实现了这个功能，但是阅读困难，可维护性很差，需要进行一次彻底的项目重构。

下面是我想到的几个具体的点：

1. 不要强行把弧形图元转换为线段图元，考虑如下数据结构：
@dataclass
class DxfGeometry:
    geom_type: str   # "LINE", "ARC", "CIRCLE", "ELLIPSE"
    params: dict     # 例如 {"start": (x,y), "end": (x,y)} 或 {"center": (x,y), "radius": r, "start": (x,y), "end": (x,y)"(圆弧起点终点)} 不同类型的元素各自定义属性
    其他需要的属性
这样后面需要对门进行处理时就不需要重新恢复圆弧信息

2. 改进门窗嵌入线提取方法。把嵌入线找准，现在的算法还不够稳，不够准确。考虑如下方法：
寻找特征图元（ARC）：遍历转换后的图元，找到 ARC 实体。门扇的扫掠轨迹通常由一段圆弧表示。提取特征点：门轴点 ($P_{hinge}$)：圆弧的圆心（Center point）。这通常绝对精确地对应门框的一侧（铰链侧）。门锁点 ($P_{strike}$)：圆弧的两个端点（Start point 和 End point）之一。过滤端点确定门宽：门块中通常还有一条代表“门扇”的小矩形，宽度很小。这个矩形的一端连接圆心 $P_{hinge}$，另一端连接圆弧的某个端点（假设为端点 A，代表门开启的状态）。那么，圆弧的另一个端点（端点 B），就是门关闭时所在的门框位置。因此，门框的两个关键坐标就是 $P_{hinge}$ 和 端点 B。连接这两点的线段长度即为门宽，方向通常与墙体平行。针对双开门：会提取到两个圆弧，直接取这两个圆弧的圆心作为门框的两个点即可。

3. 门、窗、阳台可能都放在一个图层，需要先分类。如果有圆弧，归为门；另外的根据包围盒长宽比确定，长宽比大于3，归为窗，其余归为阳台（一般是形成一个U型）。 对于窗的嵌入线，可以取包围盒较长边的中线。阳台的暂时先不考虑。

4. 提取骨架的目的服务于最后的房间分割。一般明显的房间会由墙体轴线以及门窗嵌入线围合成封闭多边形。所以为了便于后续房间识别和划分，需要先将门窗嵌入线对齐到墙体轴线上，尽可能让空间闭合。但是这部分很难定义明确的规则，还需要好好考虑

把整个任务综合考虑，重新设计一个更清晰的流程编排模块，明确每个步骤的输入输出。之前的实现比较混乱，很多步骤之间各成一套，没有统一的数据表示，没有整体架构设计，为了衔接容易做很多冗余的处理。

重构不怕把功能破坏，需要进行彻底而完全的重构，搞坏了可以再一步步把功能做好，不要被现有的实现束缚住，而无法实现真正的重构。从工程实现的角度去设计项目结构，并给重要的函数和流程加上注释，提高可读性。


## 当前实现边界

- **仅支持 DXF 输入**（已移除 JSON 读取与 JSON 绘图入口）。
- 主编排入口：`axis_engine\cad_processor.py` 中 `CADLayoutProcessor`。

## 核心流程

1. `build_geometry()`：读取 DXF，提取墙线、墙轴线、门窗聚类与嵌入线。
2. `collect_network_segments()`：将墙/门/窗语义线统一为校准输入。
3. `generate_rooms()`：线网校准后 polygonize + 矩形分解，得到房间结果。

> 调用顺序要求：必须先执行 `build_geometry()`，再调用后续步骤。若墙线/轴线/房间为空，处理器会抛出明确异常而不是静默继续。

## 最小验证脚本（cad_tests）

- `plot_wall_axes_from_dxf.py`：墙轴线提取验证。
- `plot_windows_from_dxf.py`：门窗聚类与嵌入线验证。
- `plot_constraint_calibration.py`：约束校准验证。

## 结构说明（重构后）

- `cad_processor.py`：流程编排与状态管理。
- `room_generation.py`：房间生成服务（校准 + polygonize + 矩形分解）。
